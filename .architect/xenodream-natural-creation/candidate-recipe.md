# Candidate A: constrained creation recipe

## Usage first

```powershell
$env:OPENAI_API_KEY = "..."
./dist/xenosculpt.exe create ./sculpture.xsp `
  --prompt "Make a cube and sphere composition with a cushioned sphere" `
  --model MODEL_ID `
  --export ./sculpture.xxp `
  --dry-run
```

Removing `--dry-run` publishes the workspace and optional native export. The
model returns only a seed plus zero to five controlled-language operations.
XenoSculpt parses and evaluates every operation with the existing verified
mutation layer before it writes a workspace.

## Shape

- `creation.py` owns `CreationRecipe`, seed compilation, in-memory evaluation,
  model-plan attribution, and staged workspace publication.
- `openai_planner.py` owns the Responses API request, strict JSON Schema, size
  limits, and response decoding.
- `cli.py` only parses arguments and renders the result.
- `xenosculpt.core` remains unchanged.

The admitted seed set is Cube, Sphere, Cylinder, RoundCube, Pipe, Torus, Cog,
and SpiralShell. The recipe language is exactly the existing M19/M29 grammar.
Unsupported requests are listed by the model and rejected, never silently
ignored. The final artifact hash from staged application must equal the pure
in-memory preview hash before publication.

## Tradeoffs

This adds immediate natural-language value without inventing an XDX serializer
or trusting model-generated bytes. It supports only the vocabulary already
proved by the repository. A hosted model call is nondeterministic, so the exact
returned recipe and provider response ID are shown to the user and stored as
revision provenance.
